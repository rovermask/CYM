One Key, Shared Secret

Symmetric-key encryption uses a single key for both encryption and decryption. It is fast and efficient for large data volumes, but requires a secure way to share the key between parties.

Algorithms

AES — Advanced Encryption Standard

Modern Industry Standard Block Cipher

AES is the gold standard of symmetric encryption, adopted by NIST in 2001 and used everywhere from TLS/HTTPS to disk encryption. It operates on 128-bit blocks and supports 128, 192, or 256-bit keys. AES replaced DES and remains secure against all known attacks.

128 bits
128 / 192 / 256 bits
10 / 12 / 14
2001 (NIST)
How It Works
  1. Plaintext is arranged into a 4×4 byte state matrix.
  2. SubBytes — each byte is substituted using a fixed S-box lookup table.
  3. ShiftRows — rows of the state matrix are cyclically shifted.
  4. MixColumns — each column is multiplied with a fixed polynomial (skipped in final round).
  5. AddRoundKey — the state is XORed with the round key derived from key expansion.
  6. Steps 2–5 repeat for 10, 12, or 14 rounds depending on key size.
aes_modes.txt
# Common AES Modes of Operation
ECB  - Electronic Codebook   (insecure — same block → same cipher)
CBC  - Cipher Block Chaining  (most common; requires IV)
CTR  - Counter Mode           (parallelizable; stream cipher behavior)
GCM  - Galois/Counter Mode    (AEAD — encryption + authentication)
CCM  - Counter + CBC-MAC      (used in Wi-Fi, IoT)

Real-world usage: HTTPS/TLS, Wi-Fi (WPA2/WPA3), disk encryption (BitLocker, FileVault), SSH, file compression tools, government/military communications.

DES — Data Encryption Standard

Deprecated Historical Block Cipher

DES was the dominant symmetric algorithm from the 1970s to the 1990s, developed by IBM and standardized by NIST in 1977. It uses a 56-bit key, which is now considered too short — modern hardware can brute-force DES in under a day. DES is retired but foundational to understanding how block ciphers work.

64 bits
56 effective bits
16 (Feistel rounds)
Deprecated (2001)
Feistel Structure
  1. 64-bit plaintext block is split into two 32-bit halves: L and R.
  2. In each of 16 rounds: L₁ = R₀, R₁ = L₀ XOR F(R₀, K_round).
  3. The function F includes expansion, XOR with round key, S-box substitution, and permutation.
  4. After 16 rounds, halves are recombined and a final permutation is applied.

DES was broken by EFF's "Deep Crack" in 1998 in under 23 hours. It should never be used for new applications.

3DES — Triple DES

Legacy Block Cipher

Triple DES (3DES or TDES) applies DES three times to each block using two or three separate keys, effectively extending DES's key length to 112 or 168 bits. It was a stopgap after DES became insecure but before AES was standardized.

64 bits
112 / 168 bits
~3× slower than DES
Phased out by NIST

# Encrypt-Decrypt-Encrypt (EDE)

# With 2 keys: K1 = K3 (112-bit security)
# With 3 keys: K1 ≠ K2 ≠ K3 (168-bit key, ~112-bit security)

NIST officially deprecated 3DES in 2023. Modern systems should use AES instead.

Blowfish

Unbroken Block Cipher Niche Use

Blowfish was designed by Bruce Schneier in 1993 as a fast, free alternative to DES. It uses a variable-length key (32–448 bits) and a Feistel structure with 16 rounds. Blowfish has never been broken, but its 64-bit block size makes it vulnerable to birthday attacks on large data, so use Twofish or AES instead for new systems.

64 bits
32–448 bits
16
bcrypt (password hashing)

Blowfish is the basis of bcrypt, still widely used for password hashing because its intentionally slow key setup makes brute-force attacks expensive.

RC4 — Rivest Cipher 4

Broken / Prohibited Stream Cipher Historical

RC4 is a stream cipher designed by Ron Rivest in 1987. It generates a pseudorandom byte stream (keystream) that is XORed with plaintext. RC4 was extremely popular — it powered WEP, early SSL/TLS, and many other protocols — but multiple serious biases in its output have been discovered. It is now prohibited by RFC 7465.

Stream Cipher
40–2048 bits
Prohibited (RFC 7465)

Initialize S[0..255] = [0,1,2,...,255]
Key Schedule(K) → shuffle S using K
For each byte: output_byte = S[(S[i]+S[j]) mod 256]
Ciphertext = Plaintext XOR keystream

ChaCha20

Modern Fast on Mobile Stream Cipher

ChaCha20 is a modern stream cipher designed by Daniel J. Bernstein as an improvement over Salsa20. It provides excellent performance on systems without hardware AES acceleration (like older mobile devices). Combined with Poly1305 (for authentication), ChaCha20-Poly1305 is an AEAD cipher standardized in RFC 8439 and used in TLS 1.3.

256 bits
96 bits (RFC 8439)
~3× faster than AES on no-HW
TLS 1.3, WireGuard, SSH
Quarter Round Function
  1. a += b; d ^= a; d <<<= 16
  2. c += d; b ^= c; b <<<= 12
  3. a += b; d ^= a; d <<<= 8
  4. c += d; b ^= c; b <<<= 7
  5. 20 rounds (10 column rounds + 10 diagonal rounds) are applied to a 512-bit state.

Real-world usage: Google uses ChaCha20-Poly1305 in HTTPS when AES hardware acceleration is unavailable. WireGuard VPN uses ChaCha20 exclusively.

Twofish

Secure Block Cipher AES Finalist

Twofish is a 128-bit block cipher designed by Bruce Schneier and colleagues as a finalist in the AES competition (losing to Rijndael). It supports 128, 192, or 256-bit keys, uses a Feistel structure with 16 rounds, and incorporates key-dependent S-boxes derived from the input key itself — making it highly flexible and still considered unbroken.

128 bits
128 / 192 / 256 bits
16
Unbroken / Free to use
Key Innovation
  1. Key material is split into two halves: one produces key-dependent S-boxes, the other generates subkeys via a bijective function (PHT).
  2. Each round applies MDS (Maximum Distance Separable) matrix multiplication for diffusion.
  3. Input whitening and output whitening XOR the data with subkeys before the first round and after the last.

Twofish is a strong alternative to AES and is used in some open-source tools like VeraCrypt as one of its encryption options.

IDEA — International Data Encryption Algorithm

Secure Block Cipher Patent Expired

IDEA was designed by James Massey and Xuejia Lai in 1991 and is notable for mixing three algebraic groups — XOR (⊕), addition mod 2¹⁶, and multiplication mod (2¹⁶ + 1) — in every round. This mixing of incompatible operations is what makes IDEA resistant to differential and linear cryptanalysis. IDEA was the cipher used in PGP 2.x.

64 bits
128 bits
8 full + 1 output
Expired 2012 (EU)
idea_round_operations
# Three incompatible group operations per half-round:
XOR          mod 2¹⁶       (bitwise)
Addition     mod 2¹⁶       (integer add, 16-bit wrap)
Multiplication mod 2¹⁶+1  (multiplicative group, 0→2¹⁶)

No successful cryptanalytic attacks against the full 8-round IDEA are known. It remains secure but has largely been superseded by AES for new applications.

Salsa20

Secure Stream Cipher Fast

Salsa20 is a stream cipher designed by Daniel J. Bernstein in 2005, submitted to eSTREAM and selected as a Phase 3 finalist. It operates on a 64-byte (512-bit) state initialized from a 256-bit key, a 64-bit nonce, and a 64-bit counter. Its successor, ChaCha20, improves on Salsa20's diffusion in the first few rounds and is now more widely deployed.

128 or 256 bits
64 bits
20 (Salsa20/20)
512 bits
How It Works
  1. State is a 4×4 matrix of 32-bit words formed from constants, key, nonce, and counter.
  2. 20 rounds of quarter-round operations (ARX: add, rotate, XOR) mix the state thoroughly.
  3. The original state is added back to the mixed state (counter mode), producing a 64-byte keystream block.
  4. Keystream is XORed with plaintext to produce ciphertext. Counter increments for each block.

Salsa20/8 (8 rounds) and Salsa20/12 (12 rounds) offer faster performance with reduced security margins. Only Salsa20/20 is recommended for security-critical use.

RC2 — Rivest Cipher 2

Legacy Block Cipher Avoid

RC2 is a 64-bit variable-key-length block cipher designed by Ron Rivest in 1987 for RSA Data Security. It was widely used in early S/MIME email encryption and SSL/TLS. RC2 gained notoriety in the 1990s "crypto wars" — the US government allowed RC2 export only with 40-bit effective key length as a deliberate weakness.

64 bits
8–1024 bits (effective: 1–1024)
18 (mixing + mashing)
Legacy — avoid in new systems

RC2 uses a unique key expansion algorithm (key mixing table derived from PI digits) and alternates between "mixing" and "mashing" rounds. The deliberately limited export key length made it a symbol of government-mandated cryptographic weakness. Do not use RC2 for new applications.
