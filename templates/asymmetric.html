Two Keys, Public & Private

Asymmetric (public-key) cryptography uses mathematically related key pairs. What one key encrypts, only the other can decrypt — enabling secure communication without ever sharing a secret key.

Algorithms

RSA — Rivest-Shamir-Adleman

Widely Used Encryption + Signatures

RSA, invented in 1977 by Ron Rivest, Adi Shamir, and Leonard Adleman at MIT, was the first practical public-key cryptosystem. Its security is based on the computational difficulty of factoring the product of two large prime numbers. RSA is used for key exchange, digital signatures, and encrypting small amounts of data.

1024–4096 bits (2048+ recommended)
Integer Factorization
1977
2000
Key Generation Steps
  1. Choose two distinct large prime numbers p and q.
  2. Compute n = p × q (the modulus). n is part of both public and private keys.
  3. Compute Euler's totient: φ(n) = (p−1)(q−1).
  4. Choose public exponent e such that 1 < e < φ(n) and gcd(e, φ(n)) = 1.
  5. Compute private exponent d such that d·e ≡ 1 (mod φ(n)).
  6. Public key: (e, n) — Private key: (d, n).
rsa_math
# Encryption  (anyone with public key can encrypt)
C = Me mod n

# Decryption  (only private key holder can decrypt)
M = Cd mod n

# Example: p=53, q=59, n=3127, e=3, d=2011
# Encrypt M=89: C = 89³ mod 3127 = 1394
# Decrypt C=1394: M = 1394²⁰¹¹ mod 3127 = 89 ✓

Real-world usage: TLS/HTTPS handshake (key exchange), SSH authentication, PGP/GPG email encryption, digital certificates (X.509), code signing.

ECC — Elliptic Curve Cryptography

Modern Efficient Key Exchange + Signatures

ECC is based on the algebraic structure of elliptic curves over finite fields. It provides the same security as RSA but with much smaller key sizes — a 256-bit ECC key offers equivalent security to a 3072-bit RSA key. This makes ECC ideal for mobile and IoT devices where computational resources are limited.

256 bits ≈ RSA-3072
Elliptic Curve DLP
P-256, P-384, Curve25519
TLS 1.3, Bitcoin, Signal
ecc_curve_equation
# General Weierstrass form of an elliptic curve:
y² = x³ + ax + b   (mod p)

# secp256k1 (used by Bitcoin):
y² = x³ + 7   (mod p)   where a=0, b=7

# Key generation: choose private key d (random int)
# Public key Q = d × G  (G = generator point)
# Recovering d from Q requires solving ECDLP — computationally infeasible
Point Operations
  1. Point Addition: Two points P and Q on the curve yield a third point P+Q.
  2. Point Doubling: P + P = 2P using the tangent at P.
  3. Scalar Multiplication: k × P = P + P + ... + P (k times) — the hard problem for security.
  4. The Elliptic Curve Discrete Logarithm Problem (ECDLP): given Q and G, find k such that Q = k×G.

Real-world usage: TLS 1.3 (mandatory), Bitcoin/Ethereum wallets (secp256k1), Signal Protocol (Curve25519), Apple Secure Enclave, Google's ALTS.

Diffie-Hellman Key Exchange

Foundational Key Exchange Only

Diffie-Hellman (1976) was the first public-key protocol and is still conceptually central to modern cryptography. It allows two parties to establish a shared secret over an insecure channel without ever transmitting the secret itself. DH is not used for encryption or signatures — only for key agreement.

Discrete Logarithm Problem
1976 (Diffie & Hellman)
Key Exchange Only
ECDH (Elliptic Curve DH)
dh_key_exchange
# Public parameters (known to everyone): prime p, generator g
p = 23,  g = 5

# Alice chooses private key a=6, computes public key:
A = ga mod p  →  5⁶ mod 23  =  8   (Alice sends 8 to Bob)

# Bob chooses private key b=15, computes public key:
B = gb mod p  →  5¹⁵ mod 23 = 19  (Bob sends 19 to Alice)

# Shared secret:
Alice: s = Ba mod p  = 19⁶ mod 23  = 2
Bob  : s = Ab mod p  = 8¹⁵ mod 23  = 2  ✓

An eavesdropper sees g, p, A, and B — but cannot compute the shared secret without solving the Discrete Logarithm Problem. ECDH (Elliptic Curve DH) is the modern, more efficient version used in TLS 1.3.

ElGamal Encryption

Academic / PGP Encryption + Signatures

The ElGamal cryptosystem (1985, Taher ElGamal) is based on the Diffie-Hellman key exchange. Unlike RSA, ElGamal produces ciphertexts that are twice the size of the plaintext (it is probabilistic — the same plaintext encrypted twice yields different ciphertexts). This property provides semantic security. ElGamal is used in PGP/GPG for asymmetric encryption.

DSA — Digital Signature Algorithm

Signatures Only NIST Standard

DSA is a US Federal Information Processing Standard (FIPS 186) for digital signatures, proposed by NIST in 1991. It is a variant of ElGamal that provides digital signatures but not encryption. Unlike RSA, DSA can only sign — it cannot encrypt data. DSA requires a random number (nonce k) for each signature; reusing k leaks the private key.

Signatures Only
Discrete Logarithm Problem
1024–3072 bits
Being replaced by ECDSA

A critical vulnerability: if the nonce k is ever reused or predictable, the private key can be extracted. This is exactly how the PlayStation 3's master private key was recovered in 2010 — Sony used a constant k.

ECDSA — Elliptic Curve DSA

Modern Standard Signatures Only

ECDSA is the elliptic-curve variant of DSA, offering the same security with much shorter keys. It is widely adopted in TLS certificates, SSH authentication, code signing, and blockchain transactions (Bitcoin uses secp256k1-based ECDSA for transaction signing).

Ed25519 — Edwards-curve Digital Signature Algorithm

Modern Fast & Compact Signatures Only

Ed25519 is an elliptic-curve digital signature scheme using the twisted Edwards curve Curve25519, designed by Daniel J. Bernstein. It produces 64-byte signatures from a 32-byte key and is widely considered the most practical signing algorithm available — deterministic (no random nonce required), extremely fast, and immune to several classes of side-channel attacks that plague ECDSA.

32 bytes (256 bits)
32 bytes
64 bytes
~128-bit equivalent
Why Ed25519 over ECDSA?
  1. Deterministic: The nonce is derived deterministically from the key and message, eliminating random number generator failures that have catastrophically broken ECDSA deployments.
  2. No cofactor pitfalls: Twisted Edwards curves have complete addition formulas — no special cases for point-at-infinity.
  3. Speed: Signing and verification are extremely fast, roughly 2–3× faster than RSA-2048 signing.

Used in: OpenSSH (default key type), Signal Protocol, Tor, age file encryption, WireGuard, and most modern TLS certificate authorities.

ECDH — Elliptic Curve Diffie-Hellman

Modern Key Exchange Efficient

ECDH is the elliptic-curve variant of the Diffie-Hellman key exchange. It allows two parties to agree on a shared secret using only their own private key and the other party's public key, with no pre-shared secret. Because ECC provides equivalent security to RSA with much shorter keys, ECDH dramatically reduces communication overhead.

X25519 (Curve25519)
32 bytes
TLS 1.3 default

Alice: private_a, public_A = a * G   (G = curve base point)

# Exchange public keys (A, B are safe to send openly)
Alice shared secret: S = a * B = a * b * G
Bob   shared secret: S = b * A = b * a * G  → same S ✓

# Attacker sees G, A, B but cannot find a or b
# (Elliptic Curve Discrete Logarithm Problem)

X25519 (ECDH over Curve25519) is the key exchange algorithm in TLS 1.3, Signal, WireGuard, and most modern secure messaging systems.

PGP / GPG — Pretty Good Privacy

Widely Used Hybrid Cryptography Email / Files

PGP (Pretty Good Privacy), created by Phil Zimmermann in 1991, is a data encryption and signing program that uses a hybrid cryptographic system. It combines the speed of symmetric encryption with the convenience of public-key cryptography. GPG (GNU Privacy Guard) is the free, open-source implementation of the OpenPGP standard (RFC 4880).

AES / Twofish / 3DES
RSA / ECDH / ElGamal
DSA / RSA / Ed25519
Decentralized key auth
How PGP Encrypts a Message
  1. A random session key is generated (e.g., 256-bit AES key).
  2. The message is encrypted with the session key using a symmetric cipher (AES-256).
  3. The session key is encrypted with the recipient's public key (RSA / ECDH).
  4. Both the encrypted message and encrypted session key are bundled and sent.
  5. Recipient decrypts the session key with their private key, then decrypts the message.

This hybrid approach solves asymmetric encryption's biggest problem — it's computationally expensive for large data. Symmetric encryption handles the bulk, asymmetric encryption handles only the small session key.

Paillier Cryptosystem

Homomorphic Probabilistic Research / Specialized

The Paillier cryptosystem, developed by Pascal Paillier in 1999, is a probabilistic asymmetric algorithm that supports additive homomorphism — meaning you can perform addition on encrypted values without decrypting them. This property makes it valuable for privacy-preserving computation, secure voting systems, and federated machine learning.

Decisional Composite Residuosity
2048+ bits (n = p×q)
Additive only
e-voting, federated ML
paillier_homomorphic_property
# Additive homomorphism:
Enc(m₁) × Enc(m₂) mod n² = Enc(m₁ + m₂)

# Example: compute sum of encrypted salaries without seeing them
Enc(50000) × Enc(60000) → Decrypt → 110000 ✓

Paillier is the foundation of several privacy-preserving technologies including some electronic voting systems and privacy-preserving data aggregation in IoT.
